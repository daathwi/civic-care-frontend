About CivicCare

From Citizen Voice to Accountable Governance

CivicCare is an AI-powered civic grievance platform with rich analytics, accessible via both mobile and web. Its interface adapts to each user's role — citizens, field managers, field assistants, and administrators — making it easy to report, track, and resolve MCD (Municipal Corporation of Delhi) grievances efficiently.

Unlike traditional complaint boxes, CivicCare is a complete ecosystem built for transparent civic governance. From AI-driven intelligence to public awareness, every feature is an interconnected link in the chain of accountability.

💡
Mission: From Citizen Voice to Real-Time, Accountable Governance. CivicCare digitises transparency, efficiency, and accountability — not just complaints.

Why CivicCare?

Current municipal systems face critical challenges that erode public trust:

⏱

Delayed Resolution

2,000+ unresolved civic complaints pile up due to manual routing and lack of follow-through.

🔍

No Verification

Completed tasks have no GPS-locked or photo-verified proof, leading to false closures.

📊

Limited Transparency

Citizens cannot track their complaints in real-time. There's no micro-accountability at the ward level.

Getting Started

Quick Start

Get CivicCare running locally in minutes. The platform consists of a Flutter mobile/web app, a FastAPI backend, and an AI module powered by local LLMs.

Prerequisites

Frontend

Flutter SDK 3.19+, Dart 3.3+, Android Studio or Xcode for device emulators.

Backend

Python 3.11+, PostgreSQL 15+, Ollama (for local LLM), and uv or pip for package management.

Setup

Installation

Step-by-step guide to set up both the mobile app and the backend server.

1. Clone & install dependencies

Shell 
git clone https://github.com/daathwi/civic-care-frontend.git
cd civic-care-frontend
flutter pub get

2. Configure the API URL

On first launch, you'll see the API Configuration screen. Enter your backend URL (default: http://10.0.2.2:8000 for Android emulator).

3. Run the app

Shell 
# For Android
flutter run

# For Web
flutter run -d chrome

# For iOS
flutter run -d ios

1. Setup Python environment

Shell 
git clone https://github.com/daathwi/civic-care-backend.git
cd civic-care-backend
uv venv && source .venv/bin/activate
uv pip install -r requirements.txt

2. Configure PostgreSQL

Shell 
# Create the database
createdb civiccare

# Set environment variable
export DATABASE_URL="postgresql+asyncpg://user:pass@localhost/civiccare"

3. Run the server

Shell 
uvicorn main:app --host 0.0.0.0 --port 8000 --reload

1. Install Ollama

Shell 
# macOS / Linux
curl -fsSL https://ollama.com/install.sh | sh

# Pull the LLaMA model
ollama pull llama3.2:7b

2. Verify the AI module

The MCP (Model Context Protocol) server connects to Ollama's local API. Ensure Ollama is running on port 11434 before starting the backend.

⚠️
Security Note: CivicCare uses a locally hosted LLaMA 3.2-7B model via Ollama. No data is sent to external AI services, ensuring complete data sovereignty and privacy compliance.
System Design

Architecture

CivicCare follows a modular, layered architecture designed for scalability, security, and real-time communication.

Presentation Layer
Flutter Mobile & Web App — Riverpod State · Responsive UI · Role-Based Partitioning
↕ REST API + WebSockets (JWT)
Application Layer
FastAPI Server — Domain Routers · Pydantic Validation · RBAC · Event Tracker
↕ Ollama API + MCP Protocol
Intelligence Layer
AI/MCP Server — LLaMA 3.2-7B · Contextual Filtering · Task Reasoning · Semantic Search
↕ SQLAlchemy Async Sessions
Data Layer
PostgreSQL — Users · Grievances · Wards · Departments · Events · Conversations

Frontend Architecture (Flutter)

Presentation Layer

Role-based UI partitioning with atomic widgets, feature modules (voice recording, map hub), and responsive breakpoints (mobile < 600px, tablet 600–1200px, desktop ≥ 1200px).

State & Logic Layer

Riverpod providers per domain (auth, complaints, workers, wards). Reactive subscriptions ensure real-time UI updates when data changes.

Data Access Layer

Repository pattern abstracts data fetching. API client with retry logic, multipart upload support, and JWT token refresh.

Backend Architecture (FastAPI)

Domain Routers

Independent APIRouter modules per feature set, composed into a unified API surface with /api/v1 prefix.

Pydantic Validation

Strict request/response schemas ensure data safety and auto-generated OpenAPI documentation.

Async Database

SQLAlchemy async sessions for non-blocking PostgreSQL connections. GeoJSON for ward boundaries.

AI Architecture: MCP Server

The AI module is built as an MCP (Model Context Protocol) server, providing structured tool access to the LLM. This enables the AI to query databases, analyse patterns, and generate insights through well-defined tool interfaces.

Sustainability

SDG & Impact Metrics

CivicCare maps departmental performance directly to UN Sustainable Development Goals, turning grievance resolution into measurable civic impact.

Departmental Performance Index (DPI)

A composite score that quantifies how efficiently a department serves citizens:

RE

Resolution Efficiency

Ratio of successfully resolved complaints to total received. Measures raw output effectiveness.

SLA

Service Velocity

Percentage of complaints resolved within the 48-hour SLA window. Tracks speed of response.

CH

Caseload Health

How well a department keeps its pending caseload under control. Prevents bottleneck accumulation.

RI

Resolution Integrity

First-time fix rate — how often complaints are resolved correctly without rework or reopening.

EM

Escalation Mitigation

How well the department handles problems internally without needing to escalate to higher authorities.

DPI

Overall DPI Score

Weighted composite of all five metrics. Directly maps to SDG achievement at the ward and city level.

Civic Impact Score

Measures the quality of citizen participation to encourage constructive engagement:

Developer Reference

API Reference

RESTful API with /api/v1 prefix. All endpoints return JSON. Authentication via JWT Bearer tokens.

🔑
Authentication: Include Authorization: Bearer <token> in all authenticated requests. Tokens are obtained via /auth/login and refreshed via /auth/refresh.

Authentication

POST /auth/register Register a new citizen account ▼

Body: { name, email, password, phone }

Returns: User profile with JWT access and refresh tokens.

POST /auth/login Login (citizen or department staff) ▼

Body: { email, password }

Returns: JWT tokens and user profile including role, department, and ward assignments.

POST /auth/refresh Refresh an expired access token ▼

Body: { refresh_token }

Returns: New access token.

GET /auth/me Get current authenticated user ▼

Headers: Requires Bearer token.

Returns: Full user profile including role, department, ward, tasks completed, and tasks active counts.

Grievances

GET /grievances List grievances (paginated, filterable) ▼

Query Params:

ward_id, status, priority, category_dept, reporter_id, worker_id, page, limit

Returns: Paginated list of grievances with complaint details, assignment info, and vote counts.

POST /grievances Create a new grievance ▼

Body: Multipart — includes title, description, category, subcategory, priority, lat, lng, address, ward, photo (file), audio (file, optional), isSensitive flag.

Returns: Created grievance with ID and initial status (incompleteUnassigned).

GET /grievances/:id Get grievance details ▼

Returns: Full grievance with timeline events, comments, assigned worker details, resolution image, and rating.

PATCH /grievances/:id Update grievance (status, priority, resolution) ▼

Body: { status, priority, resolutionImage } (partial update)

Permissions: Managers can update priority/status. Workers can update status and add resolution image.

POST /grievances/:id/assign Assign a field worker ▼

Body: { worker_id }

Permissions: Field Managers only.

Effect: Status changes to incompleteAssigned. Worker receives the task in their dashboard.

POST /grievances/:id/vote Vote on a grievance ▼

Body: { vote: 1 | -1 | 0 } (upvote, downvote, or remove vote)

Permissions: Citizens only.

POST /grievances/:id/rate Rate a resolved grievance ▼

Body: { rating: 1-5 }

Permissions: Original reporter only, after status is completed.

GET /grievances/:id/comments Get grievance comments ▼

Returns: Array of comments with author name, content, and timestamp.

POST /grievances/:id/comments Post a comment ▼

Body: { content }

Effect: Also broadcast via WebSocket to all subscribers of this grievance.

Upload

POST /upload/grievance-photo Upload a grievance photo ▼

Body: Multipart file upload.

Returns: { url } — path to the stored image.

POST /upload/resolution-photo Upload a resolution proof photo ▼

Body: Multipart file upload. Requires worker auth.

POST /upload/grievance-audio Upload a voice recording ▼

Body: Multipart audio file upload.

Returns: { url } — path to the stored audio.

Wards & Geography

GET /wards List all wards ▼

Returns: Array of wards with ID, name, zone, and GeoJSON boundaries.

GET /wards/lookup?lat=&lng= Lookup ward by coordinates ▼

Query Params: lat, lng

Returns: Ward that contains the given GPS coordinates. Used during complaint filing to auto-assign ward.

GET /zones List all zones ▼

Returns: Array of MCD zones.

GET /departments List all departments ▼

Returns: Array of departments with ID, name, and display name.

GET /categories List all complaint categories ▼

Returns: All categories and subcategories grouped by department.

Workers

GET /workers List field workers ▼

Returns: Array of workers with name, department, ward, active/completed task counts.

GET /workers/:id Get worker details and performance ▼

Returns: Worker profile with performance analytics, task history, and department info.

Internal Messaging

GET /internal-messages/conversations List staff conversations ▼

Permissions: Staff roles only (Manager, Assistant, Admin).

Returns: List of conversations with members and last message preview.

Citizen Guide

Everything you need to know about using CivicCare as a citizen to report and track civic issues.

Getting Started

  1. Register — Create your account with name, email, phone, and password.
  2. Configure — On first launch, enter the backend server URL if prompted.
  3. Explore — You'll land on the Dashboard with three main tabs: Dashboard, Community Feed, and My Complaints.

Filing a Complaint

Tap the + button on your dashboard to start the 3-step complaint flow:

📸 Step 1: Evidence

Capture a photo of the civic issue. Your GPS location is automatically recorded. Ensure you're at the location of the problem for accurate ward detection.

🏷 Step 2: Category

Select the department and specific issue category. Set priority (Low/Medium/High). The system will auto-detect the correct ward from your GPS coordinates.

✍️ Step 3: Details

Add a clear title and description. Optionally record a voice note. If the content is sensitive, toggle the blur option before submitting.

Tracking Your Complaints

Navigate to My Complaints to see all your filed grievances. Filter by status:

All Pending Assigned In Progress Resolved

Tap any complaint to see the full timeline, assigned worker, comments, and location on the map. Once resolved, rate the resolution quality (1-5 stars).

Community Engagement

The Community Feed shows all grievances in your ward. You can:

  • Upvote important issues to increase their visibility
  • Comment on grievances to provide additional context
  • Track neighborhood issues that affect you

Frequently Asked Questions

Common questions about CivicCare's usage, architecture, and capabilities.

CivicCare isn't just a digital complaint box. It's an end-to-end ecosystem that combines AI-powered fraud detection, intelligent worker dispatch with transparent reasoning, GPS-verified resolution proof, gamified participation scoring, and real-time SDG mapping. Every complaint moves through a verified pipeline — from submission to AI routing to GPS-locked closure — creating an unbroken chain of accountability.
Absolutely. CivicCare uses a locally hosted LLaMA 3.2-7B model via Ollama. No data — complaints, citizen information, or operational metrics — is ever sent to external cloud AI services. All AI processing happens on your own infrastructure, ensuring complete data sovereignty and GDPR/privacy compliance.
CivicCare targets 48-hour resolution for all civic complaints. If a grievance isn't resolved within this window, it's automatically escalated — moving to the Escalations tab in the manager's view and flagged in the admin dashboard. This feeds into the department's Service Velocity (SLA) metric and affects their overall DPI score.
When a grievance needs a worker, the AI analyses multiple factors: geographic proximity to the issue, the worker's expertise match for the complaint category, their current workload, and historical performance. It then recommends the optimal worker and provides transparent reasoning — for example, "Assigned because worker is closest with lowest active caseload and high resolution rate for pothole complaints." Managers can accept or override.
The Flutter app includes connectivity monitoring via the connectivity_plus package. While real-time features (WebSocket comments, live feed) require connectivity, the app gracefully handles offline scenarios by caching last-known data and showing connectivity status. Full offline-first support with sync is on the roadmap IN PROGRESS.
CivicCare is built with Flutter, providing native performance across Android, iOS, and Web from a single codebase. The responsive design adapts at three breakpoints: mobile (< 600px), tablet (600-1200px), and desktop (≥ 1200px), with sidebar navigation appearing at ≥ 800px width.
Ward boundaries are stored as GeoJSON polygons in the database, sourced from Delhi's official KML ward boundary files. When a citizen files a complaint, their GPS coordinates are matched against these polygons via the /wards/lookup endpoint to automatically determine the correct ward — no manual entry needed.
The Civic Impact Score measures the quality of a citizen's participation. You earn points for accurately filled complaints and meaningful community interactions (helpful upvotes, constructive comments). You lose points for AI-flagged irrelevant submissions and abusive/spammy behaviour. This gamified scoring encourages constructive civic engagement.
